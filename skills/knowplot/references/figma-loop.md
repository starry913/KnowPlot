# Figma 绘制与实际预览

KnowPlot 项目优先使用根目录 `figma_incremental/` 的本地图层同步插件；先读其 README 和场景格式。其他项目使用当前可用 Figma 接口或可导入 SVG。没有实际 Figma 回传图时，不得声称已在画布验收。

1. **先落宏观结构与连接。** 按已确认的 `DESIGN.md` 和一张主参考图建阶段/子图边界、相对大小、局部阶段名和短箭头。每根线从有语义的源对象边缘出发，箭头尖停在目标对象边缘；同一关系的上下游应在视觉上连续，不能碰巧接到附近的框或穿过别的对象。工具检索要画成推理节点到具体工具子框的查询线、工具子框到推理节点的结果线；外层检索区的空白不是端点。主轴方向稳定，旁支用短直线或清楚的折线接入；曲线可用，但必须比直线更清楚地表达真实关系。低保真预览应已经像一张有秩序的科研故事板，不能只是空框，更不能只有一个巨型隐喻和大片白地。把主参考图与草稿缩成相同尺寸并排比较分区、密度与视觉重量。
2. **再填区内内容。** 按 DESIGN.md 中的“分参考图局部画法 → 本论文内容”映射，在对应阶段放大小不同的语义对象、贴合文字的小框、数学排版的公式和局部结果。优先放入论文确有的检索命中、记录字段、真实案例、轨迹构成、评分条件或数据；只加术语不加信息，会让分区依然空。小框应在文字和字体确定后，依据 Figma 中实际渲染的文字范围加少量均匀内边距绘制；短标签与单条公式在框内水平、垂直居中。不能把所有框设为同宽同高，也不能靠过大空白制造宽度。若采用淡彩分区，大区用接近白色的低饱和填充且可不画外边线；小框填充与所属大区背景色完全相同，边线为该区同色系稍深的颜色。全图保留白画布、黑字与清楚的箭头对比，不能让颜色盖过科学关系。全图只用一种经实际导出验证的手写字体，包括数字和公式。指数、上下标、求和界与分式用同字体的可编辑层准确摆放，不用代码式 `exp(x)` 代替数学记号。image2 等仅制作透明底、无字、代表本论文具体对象或操作并与步骤相连的小素材；图像紧贴关键词，按真实论文展示尺寸判断是否足够大、足够清晰，不能沦为很小的装饰角标。
3. **保留可编辑性与手工微调。** 元素用稳定 ID；仅修改对应图层。增量同步前检查已有图层是否被用户在 Figma 中手工放大或移动；不改这些元素的场景属性，利用稳定 ID 和未变更的源哈希保留用户调整。删除已有元素必须写入 `delete` 列表，不能只从新 JSON 省略。图片资产保存在项目中，不只留临时目录。
4. **看 Figma 真正导出的图。** 确认预览时间晚于本轮场景修改，并同时看 100% 与预期论文缩小尺寸。第一轮与主参考图并排验收宏观分区、密度和阅读顺序，再与分参考图逐处对照局部对象；核查每枚插画是否具有内容意义，手工放大的图层是否仍保持调整，图像在缩小后能否辨认。第二轮做一次**只读箭头的检查**：从每个源对象顺着箭头走到目标对象，核对箭头方向、起落点、分叉与汇合，以及工具请求和返回、训练与评估等旁支是否被误读为同一在线循环；线名不能压住边界或让两条线看似相接。再检查淡彩分区是否真的去掉外边线、小框填充是否与所属大区背景完全一致、边线是否稍深且可辨，随后核对科学关系、文字归属、数学排版、字体回退、小框与内容尺寸、文字居中、四周内边距、遮挡和数值。最后逐区问：能否指出至少一个具体、来自论文的可见细节？空泛或拥挤都要调整。单靠“无溢出、全黑字”不代表审美通过。
5. 小问题修单层；若出现散点海报、等宽卡片模板、占据大量版面的单个装饰物，或用户否定整体构图，应回到分区与内容密度重做，另建画框。可保留旧稿准确的科学分组，但不要在被否定的视觉布局上继续换色和圆角。
6. 保存设计文档、Figma 场景、可编辑源图与 Figma 预览。说明哪些图库结构与局部素材被借鉴，以及哪些 image2 资产实际采用。Figma 暂不可用时，完成本地可用稿并明确尚未做真实画布验收。
